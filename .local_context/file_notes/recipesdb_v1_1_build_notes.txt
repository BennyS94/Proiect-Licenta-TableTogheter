# Recipes_DB v1.1 build notes

Local working memory pentru constructia Recipes_DB v1.1. Nu este documentatie persistenta de arhitectura.

## 1. Scope
- Recipes_DB v1.1 curated_200
- Food_DB gap-driven additions
- ingredient parsing
- ingredient -> Food_DB mapping
- unit-to-grams rules
- servings estimation
- nutrition cache quality
- generator readiness

## 2. Core decisions
- Main selection unit remains a complete or near-complete recipe.
- We do not return to the old model where meals are mainly assembled from separate protein + carb + veg items.
- Components/sides are allowed only as minority support/fallback.
- Food_DB = canonical ingredients.
- Recipes_DB = composed recipes.
- Meal completion may exist later as fallback, not the main mode.
- Current v1.1 target: 200 recipes, with 155 complete/near-complete meals, 20 breakfast, 10 snacks, 15 components/sides.
- Main proteins prioritized: chicken, turkey, fish, beef, pork.
- Main meals should include something next to protein: rice, potatoes, pasta, vegetables, soup/stew structure, etc.

## 3. Problems encountered
- Pilot 106 recipes were sufficient for technical generator testing but not enough for nutrition-quality generation.
- Many recipes had large ingredients unmapped.
- `servings_declared` and `servings_normalized` were missing.
- `servings_basis=1.0` inflated or distorted per-serving logic.
- Some recipe times included passive time.
- Total time needed effective-time fallback.
- Many ingredients had quantity units but no grams.
- Unit-to-grams rules were needed.
- Water/broth/salt/herbs can inflate mapped weight ratio without improving macro readiness.
- Generic meats like beef/pork/turkey are dangerous to auto-map globally.
- Bone-in meat needs edible-yield handling.
- Some local source rows had suspicious energy values and were deferred.
- Nutrition cache can still be weak even when mapped_weight_ratio looks acceptable.

## 4. Solutions/decisions found
- Use curated recipes, not random source import.
- Use draft/audit passes before touching current.
- Use safe aliases first.
- Add Food_DB items only gap-driven.
- Use conservative unit-to-grams rules.
- Mark water/broth/seasonings as low/no macro impact.
- Add `macro_relevant_mapped_weight_ratio`.
- Use edible yield for bone-in chicken/pieces.
- Collapse potato cultivars to generic potato only for macro draft and only when not prepared dish.
- Butter can use generic/unsalted 82% fat for macro draft.
- Avoid broad auto-mapping for generic beef/pork/turkey.
- Keep suspicious or ambiguous items deferred.
- Do not materialize v1.1 until nutrition cache is good enough.

## 5. Deferred decisions
- Red potatoes / Yukon gold potatoes need controlled handling.
- Chicken thighs exact source remains suspect.
- Bone-in chicken pieces need edible-yield decisions.
- Turkey / ground turkey need exact source/item decisions.
- Generic pork and generic beef remain review, not global auto-map.
- Pork neck bones remain deferred.
- Rice vinegar variants remain unsafe/deferred.
- Tomato sauce remains deferred due to suspicious energy.
- Some recipes may need replacement if low macro persists after mapping/servings checks.

  - reject if two or more lunch/dinner meals have main realism issues.
  - review if `adjusted_day_loss` is `0.12..0.20`, carbs ratio is `0.60..0.75`, one main meal has realism issues, or a borderline portion exists.
